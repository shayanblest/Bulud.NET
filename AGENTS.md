# Contributor guide

Read [RULE.md](RULE.md) before planning, changing, reviewing, or validating repository work. It defines the mandatory issue-to-PR workflow and delivery gates.

For package boundaries, project ownership, dependency direction, or .NET 10 migration work, read [docs/architecture/target-architecture.md](docs/architecture/target-architecture.md).

For domain terminology, read [CONTEXT.md](CONTEXT.md). For GitHub Issue and Beads conventions, read [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).

Keep changes narrowly scoped to the assigned issue. Preserve provider behavior during the architecture migration; move code mechanically unless the issue explicitly authorizes behavioral change.
